# 技能目录管理 / Skill catalog

左侧栏的全局入口，打开一个跨会话的技能目录页，用来集中查看和切换当前会被本地技能提供器扫描到的技能。

> 维护/开发请先读 `AGENTS.md`：架构、数据流、踩过的坑、重载与测试命令都在那里。本文只面向使用者。

- **按来源分组**：项目 `.dsh/skills`、项目 `.agents/skills`、自定义目录、用户 `~/.dsh/skills`、用户 `~/.agents/skills`、内置根。项目根按已注册的工作区逐个解析（最近的 `.git` 祖先），因此不同会话所在的仓库都能出现在同一页。
- **数据来源**：页面直接扫描这些根目录，而不是查询全局技能注册表。技能的识别规则与本地提供器一致：顶层目录里的 `SKILL.md` 或顶层的 `*.md` 文件，frontmatter 必须有合法的 kebab-case `name`、非空 `description`，两个 invocation 字段必须是布尔写法。扫描根取自宿主当前组合里的技能提供器配置，包括预设 `dsh-agent-preset` 子行声明的自定义目录。
- **两个可见性开关**：取消「对模型可见」会写入 `disable-model-invocation: true`，取消「用户可调用」会写入 `user-invocable: false`；重新勾选会移除对应字段，恢复默认允许。只改动 `SKILL.md` frontmatter 中的这两个顶级键，其余 frontmatter、注释和正文保持不变。
- **立即生效**：写入后向 `fs/observed` 发送与内建 `edit`/`write` 工具相同的变更观察，技能提供器会同步失效并重新扫描；写入完成后直接读回该文件确认两个字段已是目标状态。
- **扫描根只读展示**：直接展示当前生效的技能根路径与存在状态，不提供新增、删除或修改配置的操作；不存在的目录默认隐藏，标题右侧的按钮可以按需显示；列表按「全局在前、项目在后」排列（用户 · DSH、用户 · Agents、自定义、内置，然后是项目根），全局目录不用往下滚。存在的根可以点「打开文件夹」在系统文件管理器中打开。
- **打开文件夹**：Windows 上通过编码后的文件 URI 交给 Explorer，并保留可见窗口——隐藏式启动会连 Explorer 的文件夹窗口一起藏掉，这个坑已经规避；安装包（`.asar`）里的目录无法用文件管理器打开，按钮会禁用并说明原因。
- **安全边界**：服务端每次请求都重新计算当前扫描结果，只接受确实出现在扫描结果里的文件路径；改写前会检查 frontmatter 结构，写文件使用版本保护，文件被其他程序改动时返回冲突而不是覆盖。

## 限制

- 只显示本地文件系统里的技能；插件用 `ctx.skills.register()` 注册、没有 `SKILL.md` 的运行时技能不会出现，也不计入统计。
- 同名的技能如果被更高优先级扫描根覆盖，会带 `shadowed` 标记，页面提示里说明改动不影响模型看到的版本；文件层没有可写的 dedupe 信息，所以不会隐藏这些行。
- 内置安装归档（`app.asar`）里的技能只读展示，勾选会被拒绝。
- 只编辑 `disable-model-invocation` 与 `user-invocable` 两个字段，不支持编辑技能正文、名称或描述。
- 页面通过宿主 `/api` 路由读取数据，因此需要 Harness 的 Web 端连接；宿主半未加载时页面会显示错误并可重试。

## 安装

这是一个本地 Bundle：`package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`，后者只插入一个宿主插件行；浏览器半通过 `dsh.client` 声明为 Web 平台入口。
